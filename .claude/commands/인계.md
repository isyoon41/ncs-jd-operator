---
description: 작업을 인수인계서로 정리하고 커밋한 뒤 GitHub에 푸시한다
---

이번 세션(또는 지금까지의 작업)을 다음 담당자(Codex, 다른 Claude 세션 등)에게 넘길 인수인계서를 작성한다.

1. 오늘 날짜로 `docs/HANDOFF_YYYYMMDD.md`를 새로 만들거나, 같은 날짜 파일이 이미 있으면 최신 상태로 덮어쓴다.
2. AGENTS.md의 "인수인계 프로토콜 > 세션 종료 시" 섹션에 정의된 아래 항목을 전부 채운다. 이전 인수인계서가 있다면 그 형식을 그대로 따른다:
   - 프로젝트 개요 (경로, 스택, Supabase 프로젝트 ID, 배포 URL, 최신 커밋)
   - 오늘 작업 내용 (이번 세션에서 실제로 한 일)
   - 현재 상태 (git status가 clean인지, 브랜치/원격 상태, 커밋 이력)
   - 아키텍처 핵심 패턴 (다음 세션이 반드시 지켜야 할 설계 규칙)
   - 주요 파일 경로
   - 환경변수 (키 이름만, 값은 절대 적지 않는다)
   - 미해결 과제
   - 주의사항 (함정, 커밋 금지 파일, 하지 말아야 할 것)
3. `git status`와 diff로 이번 세션의 변경 범위를 검토한다.
4. `.env.local`, 실제 서비스 키, 자격증명, 기타 비밀값이 커밋 대상에 포함되지 않았는지 확인한다.
5. 이번 세션의 변경사항과 인수인계서를 함께 커밋한다. `/인계` 자체를 커밋과 푸시에 대한 사용자의 명시적 요청으로 간주하므로 별도로 확인하지 않는다.
6. 현재 브랜치를 `origin`에 푸시한다.
7. 커밋 해시와 푸시 결과를 사용자에게 보고한다. 실패한 단계가 있으면 실패 원인과 남아 있는 로컬 상태를 정확히 알린다.
