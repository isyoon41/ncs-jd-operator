## 아키텍처 핵심 패턴

이전 인수인계서(`HANDOFF_20260804.md`)의 패턴은 모두 유효하다. 이번 세션에서 추가/변경된 것만 기록한다.

- **`maxDuration`은 `page.tsx`에 선언**: Server Action 파일이 아니라 그 액션을 호출하는 페이지 컴포넌트 파일에 `export const maxDuration`을 선언해야 Next.js가 인식한다.
- **회사 프로필 재사용이 기본 경로**: 조직에 이미 `organization_profiles`가 있으면 사용자가 아무것도 입력하지 않아도 기존 프로필을 그대로 쓴다. 화면에서도 이걸 기본 경로로 보여줘야 한다(입력란을 항상 노출하지 말 것).
- **`reasoningNotes`/`mission`/`vision`/`coreValues`는 필수 필드**: `TeamDesign`과 `CompanyContext`에 추가된 이 필드들은 스키마상 required다. 이 타입을 수동으로 리터럴 생성하는 코드(`jobs/[id]/edit/actions.ts`의 `draft: TeamDesign = {...}`)를 건드릴 때는 반드시 값을 채워야 컴파일된다.
- **MVC는 "명시 아니면 추론", 지어내기와는 다름**: `mvcBasis: "stated" | "inferred"`로 구분해서 투명성을 유지한다. 이미 확인된 사실(사업모델·고객·전략)을 근거로 압축·재구성하는 것은 허용하지만, 근거 없는 새 사실(수치·연혁·수상 이력)을 만드는 것과는 다르다 — 프롬프트에서 이 구분을 명확히 유지해야 한다.
- **PDF는 클라이언트 사이드 렌더링**: `@react-pdf/renderer`의 `usePDF()` 훅을 클라이언트 컴포넌트에서 쓴다. 서버에서 PDF를 만드는 방식(헤드리스 브라우저 등)은 Vercel Hobby 플랜에서 위험해 의도적으로 피했다.

## 미해결 과제

1. **마이그레이션 이력 정합성 (지속)**: `00004_platform_admin_global_access`, `00005_company_context_job_design`는 여전히 Supabase CLI migration history에 없다(원격 객체는 존재). `00006`은 이번 세션에 Supabase MCP `apply_migration`으로 정상 등록됐다. 로컬에서 `supabase db push`를 실행하기 전에 반드시 `supabase migration list`로 확인하고 필요하면 `migration repair`를 먼저 할 것.
2. **문체 가이드/MVC 반영 품질의 폭넓은 검증 부족**: 지금까지 실제 생성 검증은 거의 전부 "패스웨이파트너스 / 투자 심사역" 한 사례로만 이뤄졌다. 다른 산업(제조, 서비스, B2C 등)·다른 회사 규모로 추가 검증이 필요하다.
3. **검증 루프(`validateGroundedDesign`) 체크리스트가 계속 길어지고 있음**: 이번 세션에 항목을 3개 더 추가했다. 한 번의 Gemini 호출로 이 모든 항목을 실제로 다 검토하는지 별도로 확인된 적은 없다 — 체크리스트가 더 길어지면 일부만 형식적으로 통과할 위험이 있다.
4. **NCS 검색 품질 고도화, NCS 상세 데이터 보강** (이전 세션에서 이월, 미착수): 임베딩/전문검색 도입, `definition`/분류명 비어있는 행 보강.
5. **버전 이력 UI, 레거시 JD 정리 정책, 여러 직무·기업 검증, 관리자 운영 검증** (이전 세션에서 이월, 미착수).
6. **npm audit 취약점 3건(high)**: `next`가 번들한 `postcss`, `sharp`의 알려진 취약점. `npm audit fix --force`는 `next` 버전을 바꿀 수 있어 이번 세션엔 손대지 않았다. 별도로 검토 필요.
7. **PDF 기능 자동 테스트 없음**: `jd-document.tsx`/`jd-pdf-download-button.tsx`는 수동 검증만 했다. 회귀 방지용 테스트는 없다.
8. **커스텀 도메인 미설정**: 현재 `*.vercel.app` 기본 도메인만 사용 중.
9. **Sentry DSN 미발급**: 코드는 준비돼 있지만 실제 에러가 수집되고 있지 않다.

## 주의사항

- `.env.local`, 실제 Gemini/Supabase/NCS/Sentry 키, DB 비밀번호, CLI 자격증명, Vercel 프로덕션 환경변수 값은 절대 커밋하지 않는다.
- 저장소는 Public이다. 서비스 로직 공개 범위가 커지면 Private 전환 여부를 다시 판단한다.
- `TeamDesign`/`CompanyContext`에 필드를 추가하면(이번 세션의 `reasoningNotes`, `mission`, `vision`, `coreValues`처럼) 이 타입을 수동으로 리터럴 생성하는 모든 곳(`jobs/[id]/edit/actions.ts`의 `draft` 등)을 같이 고쳐야 컴파일된다. `normalizeDesign`/`normalizeReasoningNotes`처럼 안전한 기본값 처리 헬퍼를 항상 함께 만들 것.
- Gemini 프롬프트에 규칙을 추가할 때 "~하세요" 같은 느슨한 지시는 잘 안 지켜진다(MVC 1차 시도가 그랬다). "구체적으로 인용하라", "명시적으로 반영하라"처럼 검증 가능한 형태로 쓰고, **실제 생성 결과를 Supabase에서 조회해 확인**하는 절차를 습관화할 것.
- PDF 폰트 파일(Pretendard TTF, 각 2.6~2.7MB)은 `public/fonts/`에 바이너리로 커밋되어 있다. 실수로 지우거나 다른 파일로 덮어쓰지 않도록 주의.
- `@react-pdf/renderer`는 클라이언트에서만 쓴다(`usePDF()` 훅, `"use client"` 컴포넌트). 서버에서 PDF를 렌더링하는 방식으로 바꾸지 말 것 — Vercel Hobby 플랜에서 의도적으로 피한 설계 결정이다.
- Vercel Hobby 플랜은 서버리스 함수 실행시간 상한이 낮다(대략 60초대로 추정, 정확한 수치는 미확인). `maxDuration=300`을 코드에 넣었지만 실제로는 플랜 상한에 맞춰 낮게 적용될 수 있다. 지금까지는 정상 동작했지만, Gemini 응답이 느려지는 날에는 타임아웃이 날 수 있다 — 발생하면 Pro 업그레이드나 Gemini 호출 타임아웃 단축을 고려할 것.
- **커밋·푸시 정책이 이 프로젝트에 한해 바뀌었다**: 사용자가 "앞으로 수정사항은 바로 커밋·푸시해 달라"고 명시적으로 요청했으므로, 이 저장소에서는 검증 후 바로 커밋·푸시하는 것이 기본이다. 다른 프로젝트에 이 정책을 일반화하지 말 것.
- 사용자 또는 다른 에이전트의 변경이 작업 트리에 섞여 있으면 `/인계` 커밋 전에 diff로 범위를 확인한다.
