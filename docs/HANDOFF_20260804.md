## 아키텍처 핵심 패턴

- **멀티테넌시**: `organization_members`를 통한 RLS 격리. 일반 유저는 자기 조직 데이터만 조회 가능(`is_org_member()` 헬퍼).
- **온보딩 모델**: 일반 유저는 회사를 직접 만들 수 없음. 마스터 관리자(`platform_admins`)만 `create_organization_as_admin()`으로 회사 생성 → `create_invite()`로 초대 링크 발급 → 유저는 그 링크로만 가입 + 자동 연결(`accept_invite()`).
- **권한 체크는 전부 SECURITY DEFINER 함수**(`is_org_member`, `is_org_admin`, `is_platform_admin`)로 하고, `anon` 역할의 불필요한 실행권한은 명시적으로 REVOKE 해뒀음(`get_invite_info`만 비로그인 접근 허용 — 초대 링크 미리보기 용도).
- **Supabase 클라이언트 3분리**: `src/lib/supabase/client.ts`(브라우저), `server.ts`(서버 컴포넌트/라우트), `middleware.ts`(세션 자동 갱신, 루트 `middleware.ts`에서 호출).
- **NCS 데이터는 라이브 API에 의존하지 않는 방향으로 전환 중**: 정적 파일데이터를 벌크 임포트해서 우리 DB에 캐싱 → 서비스는 우리 DB만 조회. (참고 사례: `github.com/koul777/NCScope`가 같은 패턴을 씀)

## 미해결 과제

1. **git 커밋 0개, GitHub 원격 없음** — 이 인수인계 체계가 실제로 작동하려면 커밋/푸시가 필요함. 사용자에게 확인 후 진행할 것.
2. **NCS 관련정보/기준정보 API 2종** — 계속 막혀있음. 복구 대기하거나 대체 데이터원(대/중/소/세분류명, 능력단위 정의) 확보 필요.
3. **이메일 발신 신뢰성** — Supabase 기본 발신자가 일부 기업 도메인(puriogen.com)에 미도달. 커스텀 SMTP(Resend 추천) 설정은 사용자가 보류 중, 스팸함 확인 결과 대기.
4. **실제 JD 생성 기능 미착수** — 팀 미션/R&R 생성, 직무 매칭, JD 자동 생성, 기존 JD 업로드 개선 등 핵심 제품 기능은 아직 없음. DB 스키마(`jd_versions`, `jd_sections`, `jd_evidence`)만 준비된 상태.
5. **`/admin` 접근 시 조직 목록 UI 실사용 검증** — 로그인 자체는 제가 대신 할 수 없어(자격증명 입력 금지 정책), 실제 브라우저 클릭 테스트는 사용자가 1차로 해준 상태. 추가 UI 다듬기 필요할 수 있음.

## 주의사항

- `.env.local`은 git에 커밋 금지 (`.gitignore`에 이미 포함되어 있음 — 확인했음).
- NCS/Supabase 서비스 키를 코드에 하드코딩하지 말 것.
- hrdkapi 파라미터는 **대문자 스네이크케이스**(`NCS_LCLAS_CD` 등), 자격증 API는 **`dataFormat`**(`dataType` 아님) — 헷갈리기 쉬움.
- `github.com/isyoon41/chatbot`, `pleasant-talk-mate.lovable.app`(Lovable 파일럿), `github.com/koul777/NCScope`는 전부 **참고 자료일 뿐** — 코드를 그대로 가져다 쓰지 않음. 특히 NCScope의 사전 구축 DB 파일은 라이선스 확인 없이 재사용 금지.
- 회원가입/로그인처럼 자격증명 입력이 필요한 동작은 에이전트가 대신 수행하지 않음 (사용자가 직접 해야 함) — 이 정책은 향후 세션에서도 동일하게 유지할 것.
- 커밋은 사용자가 명시적으로 요청할 때만 한다 (이 문서 작성 시점 기준 아직 요청 없었음).
