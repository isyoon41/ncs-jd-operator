## 아키텍처 핵심 패턴

- **멀티테넌시**: `organization_members`와 RLS로 조직별 데이터를 격리한다. 일반 사용자는 자기 조직 데이터만 조회할 수 있다.
- **초대 기반 온보딩**: 일반 사용자는 회사를 직접 만들 수 없다. `platform_admins`만 회사를 만들고 초대 링크를 발급하며, 사용자는 해당 링크로 가입해 조직에 연결된다.
- **권한 검사**: `is_org_member`, `is_org_admin`, `is_platform_admin` 등 SECURITY DEFINER 함수를 사용하며 `anon`의 불필요한 실행권한을 제거했다. `get_invite_info`만 초대 미리보기를 위해 비로그인 접근을 허용한다.
- **Supabase 클라이언트 분리**: 브라우저용 `client.ts`, 서버용 `server.ts`, 세션 갱신용 `middleware.ts`를 구분한다.
- **NCS 데이터 전략**: 불안정한 라이브 API에 서비스가 직접 의존하지 않고, 정적 공개 데이터를 Supabase에 적재한 뒤 내부 DB를 조회한다.
- **Next.js 16 규칙**: 코드 변경 전 `node_modules/next/dist/docs/`에서 관련 최신 가이드를 읽고 breaking change와 deprecation을 확인한다.
- **Git 규칙**: 일반 작업의 커밋은 사용자가 명시적으로 요청할 때만 한다. 단, `/인계`는 인수인계서 작성·커밋·`origin` 푸시까지의 명시적 요청이다.

## 미해결 과제

1. **실제 JD 생성 기능**: 팀 미션/R&R 생성, 직무 매칭, JD 자동 생성, 기존 JD 업로드 개선 등 핵심 제품 기능은 아직 구현되지 않았다. `jd_versions`, `jd_sections`, `jd_evidence` 스키마만 준비되어 있다.
2. **NCS 상세 데이터 보강**: 대·중·소·세분류명과 능력단위 정의가 비어 있다. 막힌 API의 복구를 기다리거나 라이선스가 명확한 대체 데이터원을 확보해야 한다.
3. **이메일 도달률**: Supabase 기본 발신 이메일이 일부 기업 도메인(puriogen.com)에 도달하지 않았다. 스팸함 확인 및 Resend 같은 커스텀 SMTP 도입 여부 결정이 필요하다.
4. **관리자 화면 검증**: `/admin` 조직 목록과 초대 관리 흐름을 실제 로그인 상태에서 추가 검증하고 필요하면 UI를 다듬어야 한다.
5. **배포**: Vercel 등 운영 배포가 아직 없다.
