## 아키텍처 핵심 패턴

- **제품 원칙**: 회사 소개/IR 자료와 최소 팀 입력으로 Gemini가 회사 고유 맥락을 먼저 설계하고, NCS 근거로 검토된 JD v1.0을 만든다. 사용자는 선택적으로 보완하고 v1.x를 필요한 만큼 반복 생성한다.
- **회사 기준점이 우선, NCS는 보완**: `designBasis`가 회사에서 왜/무엇을 해야 하는지 결정한다. NCS는 표준 능력단위·과업의 외부 근거로만 쓰며, 회사 고유 책임을 무리하게 NCS에 맞추지 않는다.
- **사실과 추론 분리**: `CompanyFact.basis`는 `stated | inferred`다. 사용자 직접 입력은 stated 사실로 보며, 미확인 내용은 JD의 확정 자격요건·산업 가정으로 만들지 않는다.
- **기준점의 다단계 검토**: `analyzeCompanyContext`(사실 추출) → `refreshCompanyDesignBasis`(기준점 생성) → 독립 검토 순서다. 수동 회사 프로필 저장도 같은 기준점 함수를 사용한다.
- **팀별 컨텍스트 축소**: NCS 검색계획의 `teamContext`에는 그 팀에 필요한 회사 앵커만 담는다. 전체 회사 프로필을 JD마다 무차별 복사하지 않는다.
- **버전은 누적 저장**: `jd_versions.version_no`는 내부 순서, `version_major`/`version_minor`는 표시용 의미 버전이다. 반복 보완은 기존 행을 덮어쓰지 않고 다음 minor 버전의 새 행을 만든다. 버전 계산은 `src/lib/jd/versioning.ts`를 사용한다.
- **근거 보존은 content 기준**: `preserveUnchangedGrounding`은 직전 `design_snapshot`의 책임·자격요건을 내용 문자열로 매칭한다. index 기준으로 바꾸지 않는다.
- **NCS 검색과 선택을 분리**: 검색은 name/definition 매칭과 분류 가중치로 후보를 만들고, Gemini는 허용 후보 안에서만 매핑한다. 허용 밖 코드는 제거하되 validation finding으로 사용자에게 알린다.
- **AI 추론은 숨기지 않는다**: `basis`는 `company | team_input | ncs | ai_inference` 중 하나다. `ai_inference` 항목은 편집 화면에서 확인 대상으로 보여야 한다.
- **권한**: 조회는 `is_org_member`, 쓰기는 `is_org_admin`. UI의 `memberRole`로 쓰기 UI를 숨기되 서버 액션 권한 검사와 RLS를 최종 방어선으로 유지한다.
- **플랫폼 운영자**: `isyoon@wisdomnco.com`은 특정 회사 소속 행 없이 플랫폼 관리자 권한으로 모든 회사에 접근한다. `organization_members` 행을 만들지 않는다.
- **Next.js 16 클라이언트 전용 라이브러리**: 브라우저 API가 필요한 라이브러리는 클라이언트 컴포넌트 안에서만 사용한다. `@react-pdf/renderer`의 `usePDF`처럼 SSR이 불가한 항목은 클라이언트 컴포넌트 내부 `next/dynamic({ ssr: false })`로 분리한다.
- **DB 변경 절차**: Supabase MCP `apply_migration`으로 운영에 적용하고 동일 SQL을 `supabase/migrations/`에 커밋한다. RLS는 impersonation으로 실제 거부/허용을 검증한다.
- **검증 후 배포**: `npx tsc --noEmit`, `npm run lint`, `npm run build`, `npm test`를 모두 통과한 변경만 `master`에 푸시한다.

   - Evidence coverage가 근거 품질에 따라 구분되는지도 기록한다.

5. **후순위 제품 과제**
   - 문장별 원문·페이지 근거 추적, `ncs_qualifications` 연결, 다차원 coverage, 책임 구조 확장, NCS 임베딩/pgvector는 별도 설계가 필요하다.
   - NCS 정의 미확보 과거 전자기기 개발 코드 44개 추적, 가입 요청 UX, PDF 자동 테스트, Sentry 활성화, npm audit 취약점 검토도 남아 있다.

## 주의사항

- `.env.local`, Supabase/Gemini/NCS/Sentry 키, DB 비밀번호, Vercel 토큰, 브라우저 로그인 정보는 절대 커밋하거나 문서에 기록하지 않는다.
- **회사의 실제 사실과 AI 기준점을 혼동하지 않는다.** 새 회사 자료/사용자 입력은 `facts`로, Gemini가 재구성한 직무설계 판단은 `designBasis`로 저장한다.
- **회사 기준점은 회사별 최신 프로필에 연결해야 한다.** 프로필 목록을 합칠 때 version 내림차순의 첫 행을 보존해야 하며, Map으로 뒤의 과거 버전을 덮어쓰면 안 된다.
- **JD 반복 보완에서 직전 스냅샷 대신 v1.0을 고정 참조하지 않는다.** 항상 최신 `jd_versions`를 기준으로 다음 버전과 근거를 만든다.
- **`preserveUnchangedGrounding`을 index 매칭으로 바꾸지 않는다.** textarea 줄 순서가 바뀔 수 있으므로 content 문자열 매칭이 회귀 버그 방지의 핵심이다.
- **Gemini가 허용 후보 밖 코드를 제안해도 조용히 숨기지 않는다.** 제외는 안전상 필요하지만 finding으로 사용자에게 알려야 한다.
- AI 생성 횟수 보호 한도(현재 사용자 시간당 5건, 회사 하루 30건)는 버전 수 제한과 별개다. 반복 버전은 무제한이지만 짧은 시간 내 호출은 rate limit을 적용한다.
- `@react-pdf/renderer`의 `usePDF`는 서버 렌더링하면 안 된다. `jd-pdf-download-button-client.tsx`처럼 `next/dynamic`의 `ssr: false`로 클라이언트에서만 로드한다.
- OneDrive 동기화 폴더에서 `.next`를 지울 때는 반드시 이 프로젝트의 재생성 가능한 절대 경로임을 먼저 검증한다. 소스, `node_modules`, `.env.local`, `supabase/`를 삭제하지 않는다.
- 회사 프로필/JD/팀 RLS의 insert/update/delete에는 `is_org_admin`, select에는 `is_org_member`를 사용한다.
- 플랫폼 운영자에게 `organization_members` 행을 만들지 않는다.
- 마이그레이션 파일명은 `supabase migration new`가 생성한 실제 타임스탬프를 유지하고 다시 `000...` 순번으로 바꾸지 않는다.
- NCS 동기화 `--apply`는 운영 DB 쓰기다. dry-run 수치와 실패 목록을 먼저 확인하고 일부 실패를 `--allow-partial`로 무시하지 않는다.
- 작업 트리에 다른 사용자의 변경이 있으면 덮어쓰지 말고 diff로 범위를 확인한다.
