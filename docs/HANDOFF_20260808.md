## 아키텍처 핵심 패턴

- **제품 원칙**: 회사 소개 자료/입력과 최소한의 팀 정보로 Gemini가 NCS 근거를 연결해 JD v1.0을 만든다. 사용자는 선택적 정보를 보완해 v1.1을 만들며, NCS 근거가 검토 루프로 다시 작동해야 한다.
- **인증 라우트 그룹**: `src/app/(app)/` 아래는 인증 필수 영역이다. 공개 인증/초대/콜백 페이지는 그룹 밖에 둔다.
- **활성 조직**: `active_org_id` httpOnly 쿠키와 `getAccessibleOrganizations`/`resolveActiveOrgId`를 재사용한다. 페이지마다 조직 선택 로직을 중복 구현하지 않는다.
- **권한 단일 기준**: `is_org_member`/`is_org_admin` SQL 함수와 테이블 RLS 정책이 서버 권한의 기준이다. `team_roles`처럼 이미 "members can manage" 정책이 update/delete까지 허용하는 테이블은 서버 액션에서 추가 권한 체크 없이 그냥 호출해도 된다 — RLS가 최종 방어선이다.
- **공용 페이지 레이아웃**: 로그인 후 모든 페이지는 `src/components/layout/page-container.tsx` + `page-header.tsx`를 쓴다. 새 페이지를 만들 때 컨테이너 폭이나 헤더 마크업을 직접 손으로 다시 만들지 않는다. 히어로(`bg-slate-950` 박스) 스타일은 대시보드·JD 리포트 같은 "완성된 결과물을 보여주는" 랜딩성 페이지에만 쓰고, 입력·관리 위주 화면은 `PageHeader`를 쓴다.
- **JD 상태 흐름**: `team_roles.status`는 `jd_status` enum(`draft`|`in_review`|`approved`|`archived`)이며 "확정" UI는 `approved`로 매핑한다. 새 상태값이 필요해지기 전까지 enum이나 스키마를 건드리지 않는다.
- **JD 삭제는 cascade**: `team_roles` 삭제 시 `jd_versions → jd_sections → jd_evidence`, `role_ncs_mappings`, `jd_validation_runs`까지 FK cascade로 전부 정리된다. 별도 정리 로직을 추가하지 않는다. 되돌릴 수 없으므로 UI에서 확인 절차(현재 `window.confirm`)를 생략하지 않는다.
- **Service Role 격리**: `SUPABASE_SERVICE_ROLE_KEY`는 `src/lib/supabase/admin.ts` 등 서버 전용 코드에서만 사용한다. 클라이언트 컴포넌트에서 import하지 않는다.
- **회사 프로필 버전 관리**: 수정은 `organization_profiles.version_no + 1`의 새 행으로 저장한다. 소비 기능은 원칙적으로 조직의 최신 버전을 조회한다.
- **관리자 UI 토큰**: 관리자 화면은 `src/components/admin/ui.ts`의 공통 스타일 토큰을 사용한다(primary는 나머지 앱과 같은 `blue-600`).
- **공식 브랜드 자산**: 워드마크를 HTML 텍스트나 임의 폰트로 재구성하지 않는다. `public/brand/pathway-partners-white.png`, `pathway-partners-color.png`, `pathway-partners-mark.png`을 재사용한다.
- **검증 후 배포**: `npx tsc --noEmit`, `npm run lint`, `npm run build`를 통과한 변경만 `master`에 푸시한다. Vercel은 GitHub 푸시로 자동 배포된다.

## 주의사항

- `.env.local`, Supabase/Gemini/NCS/Sentry 키, `SUPABASE_SERVICE_ROLE_KEY`, DB 비밀번호, Vercel 토큰/브라우저 로그인 정보는 절대 커밋하지 않는다.
- Vercel CLI는 현재 로그아웃 상태다. 토큰을 코드나 셸 기록에 직접 적지 말고, 로그인 세션 또는 안전한 환경변수 방식만 사용한다.
- 도메인을 바꿀 때는 Supabase 인증 Redirect URL을 함께 계획한다. 새 도메인만 먼저 강제하면 이메일 인증/매직 링크/비밀번호 재설정 콜백이 깨질 수 있다.
- 공식 로고는 제공된 PDF/AI에서 추출한 저장소 자산을 사용한다. CSS/HTML 텍스트로 워드마크를 다시 만들지 않는다.
- 파비콘은 투명 PNG다. 흰색 배경으로 flatten하거나 기존 `favicon.ico`를 복원하지 않는다.
- `src/lib/supabase/admin.ts`를 클라이언트 코드에서 import하지 않는다.
- `deleteUserAccount`(관리자, 계정 삭제)와 `deleteRole`(JD 삭제)는 둘 다 되돌릴 수 없는 작업이다. `changeUserOrganization`은 현재 단일 소속 모델에 맞춰 기존 멤버십을 삭제한다.
- 로그인 후 페이지를 새로 만들 때는 `PageContainer`/`PageHeader`를 재사용한다 — 컨테이너 `max-w`나 헤더 마크업을 다시 손으로 만들면 이번에 정리한 통일감이 다시 깨진다.
- Claude in Chrome 브라우저 확장 연결이 세션 중간에 끊길 수 있다(관측됨). 끊기면 재시도하거나, `gh` CLI(현재 비인증 상태)·Vercel 대시보드 직접 확인 등 대체 수단이 필요하다.
- 작업 트리에 다른 사용자의 변경이 있으면 덮어쓰지 말고 diff로 범위를 확인한다.
